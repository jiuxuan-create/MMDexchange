# VRM → PMX 转换器（vrm2pmx）

把 **VRM / glTF 虚拟形象**转成 **MMD 能直接用的 PMX 模型**，纯 Python 标准库实现，
不需要 Unity、不需要 Blender、不需要装任何第三方转换器。

- 输入：`.vrm`（VRM 1.0 / VRM 0.x）、`.glb`、`.gltf`
- 输出：`.pmx`（PMX 2.0 或 2.1）+ `tex\` 目录里的贴图 PNG
- 自带图形界面，也支持命令行批量转换
- 转换时自动生成 MMD 的标准骨骼体系（含 `左足ＩＫ` 等腿部 IK）、表情、刚体与关节

> ⚠️ **转换前请确认模型的使用条款。** 很多模型禁止二次配布或改造，转换后的 PMX
> 同样受原模型的条款约束。请只在自己有权处理的模型上使用本工具。

## 一、快速开始

### 图形界面

双击 **`启动界面.bat`**。它会自动在系统里找一个带完整 Tcl/Tk 的 Python 并打开界面。

也可以直接双击 `vrm2pmx-gui.py`，或者把 `.vrm` 文件拖到它上面。

界面里：**添加文件 → 选输出目录 → 开始转换**。转完点「打开输出目录」即可。

### 命令行

```bat
python -m vrm2pmx 角色.vrm
python -m vrm2pmx 角色.vrm -o D:\MMD\model
python -m vrm2pmx *.vrm -o out --encoding utf-8 --pmx-version 2.1
python -m vrm2pmx --info 角色.vrm        :: 只看模型信息，不转换
```

在项目根目录下执行；`-o` 省略时输出到源文件所在目录。

## 三、图形界面选项

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| 单位缩放 | 12.5 | 1 米 = 多少 MMD 单位。MMD 惯例 1 单位 ≈ 8cm，即 1 米 ≈ 12.5 单位 |
| PMX 版本 | 2.0 | 2.0 兼容性最好；2.1 支持 QDEF 等新特性 |
| 文本编码 | UTF-16LE | MMD 惯用 UTF-16LE；个别工具需要 UTF-8 |
| 描边宽度 | 1.0 | 轮廓线粗细，配合「生成描边」使用 |
| 生成描边（轮廓线） | 开 | 写材质 flag 的 EDGE 位 |
| 脚底对齐到 y=0 | 关 | 源模型悬空/陷地时用；默认按 VRM 原始坐标 |
| 生成物理（刚体/关节） | 开 | 由 SpringBone / 碰撞体生成 |
| 自动补物理链 | 开 | 模型没有 SpringBone 时，按骨骼名关键词（hair/skirt/tail…）自动串链 |
| 生成表情 | 开 | 预设表情 + 自定义表情 |
| 保留额外骨骼 | 开 | 保留 VRM 里挂载的非人形骨 |
| 垂直翻转 UV | 关 | 贴图上下颠倒时勾选 |

命令行参数与上表一一对应，见 `python -m vrm2pmx --help`。

## 四、转换都做了什么

### 1. 坐标系与尺度（最关键的一步）

MMD 的模型**面朝 −Z**，glTF/VRM 的模型**面朝 +Z**；两者绕序约定都是"面法线·顶点法线 > 0"。
所以变换 `(x, y, z) → (x, y×S, −z×S)` 是一个**镜像**（行列式 −1），必须把每个三角形的
索引顺序由 `(a,b,c)` 改成 `(a,c,b)`，否则模型会**从里朝外**。

这两条结论不是猜的，是用参考 PMX 实测出来的（见第七节）。

S = 单位缩放，默认 12.5。

### 2. 骨骼

- VRM humanoid 的 54 根骨 → MMD 标准名（`hips→センター`、`spine→上半身`、
  `upperChest→上半身3`、`head→頭`、`leftLowerArm→左ひじ`、`leftUpperLeg→左足` …）
- 手指按 MMD 惯例写成 `左親指０/左親指１/左親指２`、`左人指１..３`、`左中指…`、
  `左薬指…`、`左小指…`（全角数字，MMD 只认这个写法）
- 自动补齐 MMD 需要的中间骨：`全ての親 / センター / グルーブ / 腰 / 上半身2 / 上半身3 /
  両目 / 足IK親`
- **腿部 IK**：生成 `左足ＩＫ`、`左つま先ＩＫ`（全角ＩＫ），目标、迭代次数、
  `ひざ` 的 −162.5°~−0.5° 角度限制都照参考模型的实测值配置
- `左目/右目` 用「付与」指向 `両目`，能跟着视线控制骨转

### 3. 网格

- 按材质分组输出，保持材质索引连续、`index_count` 之和等于索引总数
- 蒙皮：单骨/双骨/四骨权重分别写成 BDEF1 / BDEF2 / BDEF4，权重归一
- 法线：源文件有就用，没有就按几何法线补

### 4. 材质与贴图

- baseColor / MToon 的 shadeColor、outlineColor、MatCap 等 → PMX 材质的
  diffuse / ambient / sphere / edge 字段（**近似映射**，不是一比一）
- 贴图从 GLB 里解出来写成 PNG，路径用反斜杠相对路径（`tex\000_皮肤.png`），
  按 MMD 习惯放在 `tex\` 子目录
- 只输出真正被网格用到的材质，不产生 `index_count=0` 的空材质

### 5. 表情

- VRM 预设 → MMD 常用表情名：`blink→まばたき`、`aa→あ`、`happy→笑い`、
  `angry→怒り`、`sad→困る`、`relaxed→にこり`、`surprised→びっくり`，
  视线类 `lookUp→目上` 等
- 自定义表情**保留原名**，不做翻译
- 面板按名字归类到 眉/目/口/その他
- 同时生成顶点表情与材质颜色表情

### 6. 物理

- `VRMC_springBone`（VRM 1.0）与 `secondaryAnimation`（VRM 0.x）两条路都支持
- 碰撞体 → 骨骼追従刚体（组 1）；物理链 → 物理刚体（组 2 起），
  `no_collision_group` 只与组 1 碰撞
- 胶囊刚体的位置取骨骼段**中点**、长轴为**局部 +Y**、旋转按 `R = Rx·Ry·Rz` 反解
  —— 这三条都是从参考模型的 151 个刚体里统计出来的
- 关节用 SPRING6DOF，弯曲/扭转上限与弹簧常数由 stiffness / drag 映射

### 7. 生成的 PMX 还会写入什么

- 8 个表示枠：`Root / 表情 / ＩＫ / 体(上) / 腕 / 指 / 足 / その他`
- PMX 注释里写入 VRM 的名称、作者、授权条款，便于溯源
- 输出文件名默认取 VRM 里的模型名（非法字符替换）

## 六、已知限制（请如实预期）

1. **顶点表情上限**：MMD 每个顶点最多受 4 个顶点表情影响。表情多的模型（真实样本里有
   2159 个顶点被 >4 个表情影响）在**极端组合**下会丢一点效果，转换时会给出警告。
2. **材质是近似映射**：MToon 的卡通着色、阴影色、描画在 PMX 里没有对应概念，
   映射到传统材质字段后观感会变，通常需要在 PMX Editor 里微调。
3. **物理需要人工微调**：stiffness / drag → 阻尼与弹簧常数是启发式映射；
   没有 SpringBone 时的自动串链纯靠骨骼名关键词，效果以实际摆动为准。
4. **只处理三角网格**：`mode != 4` 的 primitive 会被跳过。
5. **法线沿用源数据**：源模型本身有反面三角形的话会照原样保留（真实样本 36470 个三角形里
   有 6 个反向，来自源数据本身）。
6. **不支持的扩展会被忽略**：如 `VRMC_node_constraint`、部分 `KHR_materials_*`。
   转换会在日志里提示。
7. **不做 A-pose → T-pose 的姿态重定向**：按源模型的静止姿势原样输出。
   MMD 里如果姿势不对，需要在 PMX Editor 里调整。
8. 输出 PMX 2.1 时追加 UV 数量为 0（不搬运追加 UV）。

## 七、这些约定是怎么定下来的

PMX 的朝向、绕序、刚体几何、欧拉角顺序、尺度，都不是从文档里抄的，而是把参考模型
`千夏 KFC V1.2.pmx` 完整解剖后统计出来的。参考模型属于第三方作品，其解剖报告不随本
仓库分发——用下面的工具对**你自己的**模型跑一遍，就能得到同样的报告并复核结论：

```bat
python tools\inspect_pmx.py "模型.pmx" --full      :: 结构总览（含 IK 详情），即解剖报告
python tools\probe_winding.py "模型.pmx"            :: 绕序与朝向
python tools\probe_rigid_rotation.py "模型.pmx"     :: 刚体旋转约定反推
python tools\inspect_vrm.py "模型.vrm"              :: VRM 结构
python tools\check_refs.py "模型.pmx"               :: 引用有效性体检
```

几条最贵的结论：

- **面朝 −Z、左 = +X、Y-up 左手系**：用「面部系材质顶点相对 `頭` 骨骼的 Z 偏移」投票，
  11 个面部材质平均 **−0.6719 单位**；旁证 `左つま先.z − 左足首.z = −1.3917`。
  同时 `左目.x − 右目.x = +0.2910`。
- **绕序与 glTF 同向**：抽查 53646 个三角形，`(v1−v0)×(v2−v0)·法线 > 0` 的有 53623 个。
  所以镜像后必须反转索引顺序。
- **1 米 = 12.5 个 MMD 单位**：`頭` 骨骼高 15.4552 单位、顶点最高 18.312 单位。
- **胶囊刚体**：位置 = 骨骼段中点（前 10 个胶囊与中点距离多为 0.000），
  `size = (半径, 段长, 0)`，长轴 = 局部 +Y；欧拉顺序 `R = Rx·Ry·Rz`
  （全样本 ZYX 0.9528 vs ZXY 0.9519，属高置信但非硬证据）。

```
│   ├─ gltf.py             glTF 2.0 / GLB 容器解析
│   ├─ vrm.py              VRM 0.x / 1.0 语义统一层
│   ├─ transform.py        坐标与尺度变换
│   ├─ mmd_bones.py        骨骼映射 + 控制骨 + 腿部 IK
│   ├─ mesh.py             网格（索引反转 / 蒙皮 / 法线）
│   ├─ materials.py        材质与贴图池
│   ├─ morphs.py           表情
│   ├─ physics.py          SpringBone / 碰撞体 → 刚体 / 关节
│   ├─ convert.py          总装
│   ├─ cli.py              命令行入口
│   ├─ gui.py              Tkinter 界面
│   └─ probe_tk.py         探测某解释器能否开窗口
├─ tests\                  测试（run_all.py 一键跑完）

└─ output\                 转换产物
```

> 参考素材不随仓库分发：测试用的参考 PMX / 真实 VRM 请自备，用环境变量
> `VRM2PMX_REF_PMX`、`VRM2PMX_REAL_VRM` 或 `VRM2PMX_SAMPLES` 指定，详见 `tests\sample_paths.py`。

## 九、关于同类工具

本工具是**从零实现**的（clean-room），没有使用任何第三方转换器的代码。
B 站上的开源工具 **VRMify** 做的是反方向的 **PMX → VRM**，同样基于
`Model-To-PMX` 的思路，以 GPL-3.0 发布；本项目的代码与其无关。

参考模型用于**格式研究**，其版权与使用条款归原作者所有，本项目只提取格式层面的
统计规律（朝向、绕序、缩放、刚体几何），不复制模型数据。
